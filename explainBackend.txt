FlowerApplication Backend System
================================

Overview
--------
The backend is a Node.js/Express API backed by MongoDB (Mongoose). It exposes versioned REST endpoints under /api/v1 and serves Swagger UI at /api-docs. It uses JWT authentication, role-based access control, centralized error handling, and standard pagination/sorting helpers.

Startup Flow
------------
1. backend/src/server.js
   - Loads environment variables from backend/.env.
   - Validates required env vars (MONGO_URI, JWT_SECRET).
   - Connects to MongoDB, then starts the HTTP server.

2. backend/src/app.js
   - Creates the Express app.
   - Adds middleware: CORS, JSON body parsing.
   - Serves Swagger UI at /api-docs using backend/src/docs/openapi.yaml.
   - Mounts all routes under /api/v1 and keeps /api as a legacy alias.
   - Adds centralized 404 and error handlers.

Environment Configuration
-------------------------
- backend/.env holds secrets and runtime configuration.
- backend/.env.example documents required variables.
- backend/src/config/env.js enforces required variables at startup.
- Root .gitignore prevents committing .env files.

Centralized Error Handling
--------------------------
- backend/src/middleware/errorHandler.js provides:
  - notFound middleware (404 for unknown routes).
  - errorHandler middleware (统一 JSON errors, CastError/ValidationError handling).
- Routes use next(err) to send errors into the centralized handler.

Pagination, Filtering, Sorting Standards
-----------------------------------------
- backend/src/utils/query.js defines shared query helpers.
- Standard query params:
  - page (enables pagination when provided)
  - limit (page size, max 100)
  - sort (comma-separated fields, prefix '-' for descending)
  - fields (comma-separated projection)
- When page/limit is used, list endpoints respond with:
  { data: [...], pagination: { total, page, limit, pages } }
- Implemented on common list endpoints (flowers, orders, users, admin users, categories, cities, promotions).

Authentication and Authorization
--------------------------------
- backend/src/middleware/authMiddleware.js verifies JWT and sets req.user.
- backend/src/middleware/requireRole.js enforces role-based access.

Indexes and Optimization
------------------------
- Orders: compound indexes on floristId+status+createdAt, userId+createdAt, deliverId+status+createdAt, and items.flowerId.
  - Justification: most order list endpoints filter by status/userId/floristId/deliverId and sort by recency; indexing these patterns reduces scan cost and improves pagination.
- Flowers: compound indexes on categoryId+available+price, floristId+available+createdAt, city+available+createdAt.
  - Justification: flower browsing/search endpoints filter by category/city/availability with price ranges and sort by createdAt for "popular/newest" lists.
- Favorites: unique compound index on userId+flowerId to prevent duplicates and speed up per-user favorite lookups.
- Existing unique/compound indexes: User.email, City.name, Order.orderNumber, and Connection compound indexes.
